# 答辩演示指南

## 演示前检查

```bash
python -m unittest discover -s tests -v
python scripts/seed_demo.py
python app.py
```

确认浏览器首页首先显示“毕业项目”。建议提前准备两类问题：一类是原文事实问题，另一类是实体关系问题。

## 五分钟演示流程

1. 打开“文档索引”，上传 `data/` 中的两份示例文档。
2. 展示系统返回的文本块数量和实体关系数量。
3. 在“智能问答”中选择“向量检索”，询问：`证监会明确的监管工作主线是什么？`
4. 展示答案中的 `[证据1]`、来源和发布日期。
5. 切换为“融合检索”，询问：`监管政策如何影响证券业？`
6. 打开“实体关系”，说明方向箭头和关系来源。
7. 在最后明确说明：系统是证据问答原型，不提供投资建议。

## 常见答辩问题

### 为什么需要图谱，向量检索不够吗？

向量检索擅长找到语义相近的文本，但公司、政策、行业和事件之间的多跳关系可能分散在多个文本块中。图谱把关系显式保存，并通过 `chunk_id` 回到原文。

### 为什么使用上下文融合而不是直接相加得分？

向量相似度和图谱置信度的含义不同。项目采用 RRF 根据排序名次融合，避免把不同量纲的分数直接相加。

### Neo4j 是否真的参与查询？

当 `GRAPH_BACKEND=neo4j` 时，索引阶段使用 `MERGE` 写入实体和有向关系；问答阶段使用一至四跳的 Cypher 路径查询。默认 SQLite 只是为了保证离线演示。

### 如何降低幻觉？

系统 Prompt 要求仅依据检索证据回答；证据不足时拒绝下结论；答案按 `[证据N]` 标注，并展示文件、页码和日期。实际产品还应加入引用一致性自动评估。

### 项目的主要工程贡献是什么？

双后端可切换架构、金融实体方向关系、图谱证据回链、向量与图谱的 RRF 融合，以及无需外部服务的答辩后备模式。
